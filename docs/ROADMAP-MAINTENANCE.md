# NetOps — регламент ведения ROADMAP

## Куда писать

- [ROADMAP](ROADMAP.md) — приоритеты, открытые задачи, актуальные блокеры, ссылки на действующие решения и архив. Одна строка на активную инициативу. У строки есть статус, следующий шаг и ссылка на Issue, PR или локальный план.
- [STATE](STATE.md) — снимок текущего состояния для исполнителя. Обновлять его при значимом изменении SHA, статуса, блокера или ответственности. Перед использованием сверять с актуальным `main` и GitHub.
- [DEVELOPMENT_WORKFLOW](DEVELOPMENT_WORKFLOW.md) — действующий порядок проверок и выпуска, [NETOPS_DECISIONS](../NETOPS_DECISIONS.md) — долгосрочные решения. При замене решения отметить дату и преемника.
- Issue, PR, `docs/audits/` и профильные планы — детали реализации, audit evidence, поимённые результаты и команды воспроизведения. Из дорожной карты давать адресные ссылки.
- [Архив](ROADMAP-ARCHIVE.md) — датированные выпуски завершённых, отменённых и заменённых записей. При повторном открытии создать короткую активную строку со ссылкой на архив.

## Как обновлять

1. При изменении статуса обновить существующую строку. При закрытии перенести историю в выпуск архива, указать дату и результат, PR/Issue, полный SHA проверенной ревизии и ссылки на CI, отчёт и артефакты, если они есть. Отдельно записать состояние технической, опубликованной и личной приёмки. Если доказательство ещё ожидается, указать это прямо.
2. Исторические записи сохранять целиком, включая прежние статусы. Ссылки на старую редакцию фиксировать по SHA. Новые архивные выпуски хранить в `docs/` по схеме `ROADMAP-history-ГГГГ-ММ-<тема>.md` и добавлять в указатель. Для каждого выпуска ориентир — до 64 КиБ, граница между целыми записями.
3. При каждом PR с изменением ROADMAP проверить размер UTF-8 и список активных строк. Рабочий предел — **10 КиБ и 80 строк**. Если запись выводит за предел, перенести подробности в профильный документ или закрытые записи в архив в том же PR. Если все задачи ещё открыты, сгруппировать обзор по направлениям и дать ссылки на их очереди.
4. При закрытии пакета и на еженедельной сверке координатор проверяет статусы, ссылки и появившиеся блокеры. Если запись переносится, проверить входящие ссылки в репозитории. Для ссылок вне репозитория использовать закреплённый снимок по SHA и указатель архива.
5. Передать агенту [STATE](STATE.md) и обязательные для его контура стандарты обычным способом. Для выбора приоритета читать ROADMAP целиком. Для расследования читать указатель и нужный выпуск архива. Этот порядок подходит и при ручной проверке, без дополнительных CI-гейтов.
