# Gemini-разработчик через GitHub Issues

## Отдельный синтетический пилот

Подготовлен отдельный `Gemini DEV synthetic one-shot pilot`, выключенный по
умолчанию. Обычная блокировка `[GEMINI DEV]` не снимается. Перед пилотом нужны
независимая приёмка, зелёный CI, подтверждение владельцем бюджета и проверка тарифа
и условий передачи данных именно API-проекта. Лимиты запросов и токенов не гарантируют
денежный потолок. Владелец отдельно устанавливает
`NETOPS_GEMINI_PILOT_ENABLED=true` и `NETOPS_GEMINI_DEV_PROVIDER_VERIFIED=true`,
после чего запускает workflow с подтверждением `one-synthetic-request`.

Отправляется только фиксированный вымышленный текст и инструкция на JSON без
STATE, стандартов, исходников, поиска или инструментов. Предел запроса 4096 байт,
выхода 2048 токенов, общего времени HTTP 60 секунд и тела ответа 65536 байт. До запроса
атомарно создаётся постоянный checkpoint единственной попытки; повторный запуск
или таймаут не разрешают ещё один запрос. Удалять checkpoint для повтора нельзя.
Корректный ответ может создать только `docs/gemini-dev-pilot.md`, проходит
общие sandbox-проверки и публикуется отдельным Draft PR. Неизвестная стоимость
не считается нулём. Пилот не выполняет merge или deploy.

Маршрут `[GEMINI DEV] ` после слияния PR #457 в `main` остаётся выключенным
для вызовов модели до отдельного решения владельца. Владелец `apotet` создаёт Issue `[GEMINI DEV] <название задачи>` с JSON в теле.
Создание Issue не вызывает модель. Пример конфигурации будущего пилота (не запускать
до отдельного разрешения):

```json
{
  "task": "Создай новый docs/gemini-dev-pilot.md с одной строкой: NetOps Lab Gemini developer pilot.",
  "mode": "edit",
  "model": "gemini-3.8-flash",
  "context_files": [],
  "write_paths": ["docs/gemini-dev-pilot.md"],
  "max_calls": 1,
  "max_total_calls": 1,
  "max_output_tokens": 2048
}
```

После отдельного согласования обращения к API владелец добавляет к своему Issue
комментарий. Для продолжения подставьте полный 40-символьный SHA из последнего
отчёта этого Issue и дождитесь завершения предыдущего запуска.

| Действие | Точный текст комментария |
| --- | --- |
| Начать | `/agent start confirm-paid-api` |
| Разрешить ещё один вызов | `/agent continue {"checkpoint":"<SHA>","calls":1}` |
| Продолжить после HTTP 429 или другой неопределённой попытки | `/agent continue {"checkpoint":"<SHA>","calls":1,"acknowledge_uncertain":true}` |
| Повторно проверить сохранённый кандидат без модели и публикации | `/agent validate {"checkpoint":"<SHA>","calls":0}` |
| Опубликовать уже проверенный кандидат без модели | `/agent publish {"checkpoint":"<SHA>","calls":0}` |

Для HTTP 429 сначала проверьте квоту Google. Попытка резервируется до запроса,
код HTTP сохраняется, а непроверенное тело ошибки или некорректный ответ удаляется.
При достижении лимита вывода сохраняется только проверяемый префикс JSON из
завершённого транспорта, если граница не оборвала значение. Повтор возможен только с явным подтверждением неопределённой
попытки и в пределах общего лимита задачи; в пилоте после первой попытки повтор
невозможен. `calls: 0` заменяет прежний остаток разрешённых вызовов нулём.

`max_calls` по умолчанию 8 на старт; `max_total_calls` по умолчанию и максимум 8
на всю задачу с продолжениями. `max_output_tokens` по умолчанию и максимум
16384 на запрос. Для пилота закреплены 1 попытка и максимум 2048 выходных
токенов. Эти параметры не меняются при продолжении. Старые Gemini checkpoints
без общего лимита или записи размера прошлых попыток не разрешают новые вызовы.

Доверенный код блокирует новые вызовы Gemini DEV независимо от настроенных
переменных. Включение требует отдельного рассмотренного изменения кода и решения
владельца после проверки тарифа, обработки данных и остановки расходов именно
для используемого API-проекта. До этого переменные оставлять пустыми. После
отдельного разрешения для включения также нужны
`NETOPS_GEMINI_DEV_PROVIDER_VERIFIED=true` и оба положительных целочисленных
предела `NETOPS_GEMINI_DEV_MAX_REQUEST_BYTES` и
`NETOPS_GEMINI_DEV_MAX_TOTAL_REQUEST_BYTES`. Первый ограничивает размер
сериализованного UTF-8 запроса; второй сумму размеров всех попыток задачи, включая
неопределённые. Пределы проверяются до запроса, расход каждого запроса резервируется
в checkpoint. Пока блокировка в коде включена или отсутствует любое из трёх
значений, Start/Continue не делают ни одного обращения к модели. Это операторское подтверждение, а не автоматическая проверка
аккаунта, и ограничение объёма данных, а не денежный или суточный лимит.

Дневную квоту проекта и модели контролирует Google. Runtime
показывает попытки и доступные usage, а стоимость Gemini помечает неизвестной.
Лимит токенов и число попыток не являются финансовым потолком: до запуска владелец
должен настроить внешний лимит расходов у провайдера и убедиться, что он действительно
останавливает платное использование. Если такого ограничения нет, бесплатность не гарантируется.
Модель `gemini-3.8-flash` ранее присутствовала в диагностике с методом
`generateContent`. Доступ к генерации и тариф нового маршрута требуют
отдельной проверки с разрешения владельца.

Используется существующий `GEMINI_API_KEY`. API получает текстовый контекст
включая выбранные исходники и обязательные стандарты. Перед отправкой проверьте
условия обработки данных Google для вашего тарифа. Непрозрачные бинарные
данные, включая изображения, отклоняются; `context_files: []` не отключает
обязательные STATE и стандарты.

Успешное редактирование проходит sandbox-проверки, затем публикуется в
`gemini/issue-<номер>` и Draft PR в `main`. После создания ветка неизменяемая:
для другого кандидата нужна новая задача. Это исключает изменение принятой PR
при гонке смены Draft-статуса. Восстановление повторно использует тот же commit.
Независимая приёмка остаётся обязательной. Merge и deploy агент не выполняет.

## Существующий аудитор

При разрешённом обращении к API владелец создаёт отдельный Issue
`[GEMINI] <название аудита>`. Этот маршрут запускается **при создании** Issue.
Тело, например:

```json
{
  "task": "Проверь техническую точность указанного урока и верни замечания с цитатами.",
  "mode": "audit-only",
  "model": "gemini-4-hydrogen",
  "files": ["src/data/lessons/l1-poe-budget.ts"]
}
```

Подробности аудитора описаны в [GEMINI_ISSUE_AGENT.md](GEMINI_ISSUE_AGENT.md).
