# Gemini-разработчик через общий runtime

Отдельный маршрут `[GEMINI DEV] ` не заменяет старый audit-only `[GEMINI] `.
Используется существующий secret `GEMINI_API_KEY`; ключ нельзя публиковать в Issue.
Модель по умолчанию `gemini-3.8-flash`: она присутствовала в диагностике моделей
25.11.2026 с методом `generateContent`, но реальный вызов нового агента ещё не проверен.
Если модель недоступна данному ключу или квоте, задача приостановится без автоповтора.

Создание Issue само по себе не запускает этот маршрут. Пример тела:

```json
{
  "task": "Исправь указанную задачу и добавь необходимые тесты.",
  "mode": "edit",
  "context_files": ["src/data/lessons/index.ts"],
  "write_paths": ["src/data/", "tests/"],
  "max_calls": 8
}
```

Для старта владелец пишет `/agent start confirm-paid-api`. Название команды
предупреждает о возможной оплате: runtime не может проверить тариф проекта и не
гарантирует бесплатность API. Продолжение только от владельца с актуальным SHA:
`/agent continue {"checkpoint":"<SHA>","calls":1}`. `calls: 0` не разрешает
нового вызова. Ошибка транспорта или квоты сохраняет checkpoint как `uncertain`;
повтор только отдельной командой с `"acknowledge_uncertain":true`. Частичный ответ
при `MAX_TOKENS` сохраняется для продолжения, если Google вернул его текст.

`max_calls` по умолчанию 8 за запуск, `max_output_tokens` по умолчанию и максимум
16384 на запрос (защитный лимит runtime, не предел модели). Общего дневного
счётчика Gemini в runtime нет: квоту проекта и модели контролирует Google,
включая другие клиенты. Отчёт показывает количество попыток и доступные usage;
неизвестная стоимость не считается нулём. Параметры тарифа, квот и оплаты
владелец проверяет в Google AI Studio. Квота не гарантирует завершение задачи.

Контекст задания, включая выбранные файлы и обязательные стандарты, отправляется
в Gemini API. До запуска проверьте применимые условия обработки данных Google
для своего тарифа; не передавайте секреты или запрещённые к отправке данные.
Изображения в этом адаптере не передаются как изображения; визуальная проверка
должна обозначаться как непроверенная.

Результат проходит существующую sandbox-проверку и публикуется только в
`gemini/<task>` и Draft PR. Независимая приёмка обязательна; автоматического
merge/deploy нет. Действующие Gemini workflow и их квоты не изменяются.
