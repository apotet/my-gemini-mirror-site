**Действующие точки входа.** «Тесты» → параметры, пробный экзамен и существующие сохранённые попытки, «Работа над ошибками»/разбор; `TheoryView` → «Разборы вопросов», «База знаний», «OSI и TCP/IP», «Порты», «Шпаргалки L1–L7» (DOM ID `cheatsheet-l1…cheatsheet-l7`) и «Сценарии». База знаний уже даёт поиск/фильтры уроков, отдельный Cisco CLI-справочник и связанные термины. В staging есть сортировка, учебная последовательность Beginner, «Продолжить урок» после F5 и избранное; в закреплённом production это ещё не те же возможности. Палитра команд работает как ярлык для разделов/темы оформления, но **не** как индекс уроков, разборов, глоссария и CLI, поэтому не выдавать её за «глобальный поиск». Пункта «Курсы», единого реестра курсов/итогов, входа и серверной синхронизации на этих снимках нет.

**Сохранение не надо переписывать с нуля.** `osi_user_progress_v4` хранит статистику/квитанции, `osi_last_exam_review_v1` последний разбор. Staging использует `osi_active_session`; production дополнительно имеет `osi_active_session_netops_n5`, совместимость с наследованным ключом, архивирование и защиту версии/вкладок. Staging отдельно хранит `osi_knowledge_favorites_v1`, `osi_knowledge_beginner_resume_v1` и настройки фильтра; сессия и предпочтение вида текста не равны прохождению. Сайты Pages на одном домене и разных путях **не** получают раздельный localStorage автоматически; исторический сайт тоже не основание считать старые ключи изолированными. Не читать полномочия на удаление по расположению URL, не очищать и не писать существующие слоты в рамках этапа 1.

## Действующие практики и границы

| Точка входа и устойчивые ключи | Пригодность / что не обещать |
| --- | --- |
| «Практика» → `journey`; связка `packet` | Рабочий Packet Journey: видны кадр, IP и шаги ARP/ICMP. Для `l3-arp` на staging есть «Что дальше» и возврат к исходному уроку; отдельная визуальная ARP-сцена в уроке дополняет его, не подменяет стенд. Не выдавать одну схему за произвольный эмулятор. |
| «Практика» → `vlan`; общий `vlan` в обоих; отдельный `vlan-trunk-case` только staging | Обычный стенд по умолчанию свободный; закреплённое «Дело 4», PC‑02 → PC‑04, VLAN 20, SW2 не принимает 20 до исправления. Это allowed VLAN, **не native VLAN**, поэтому не привязывать к проверке native-тега. Реальная CLI-настройка — отдельный маршрут, не второй экземпляр стенда. |

| «Практика» → `cli`; Cisco CLI Lab 2.0, сценарии ниже | Целевой реальный engine с проверкой состояния. Для курсов использовать сценарии, а не макеты терминала. Сценарии специфичны для Cisco IOS, не для многовендорного исполнителя; не привязывать «похожую» команду другого вендора. |
| «IPv4 Тренажёр» / мобильный «IPv4» | Реальный калькулятор/упражнения. Контекстные ссылки staging несут точный навык/параметры; производственный снимок старше. | «IPv6 Тренажёр» / мобильный «IPv6» | Общие режимы сжатия, разворота, типа и /64. Staging направляет `review-ndp-1/2/3`, `review-slaac-4/5/6` в шесть разных упражнений; `l3-d06` оставлен в «Тип». Это задачи с обратной связью, а не NDP-эмулятор. |

### Исторические маршруты: брать пользу, не копировать сайт

| Маршрут исходного сайта | Решение для Courses |
| --- | --- |
| `index.html#course`, `#miniCourse`, `quiz/` | Источник UX-идей: короткие уроки, возврат, тест. Старый отдельный банк не импортировать в текущие итоги; потребуются аудит лицензий, ключей и дублей даже для одиночного материала. |
| `packet-journey.html`, `vlan-trunk.html` | Предшественники нынешних `packet` и `vlan`; повторно не переносить. Видимые кадры и тексты можно сравнить с текущими сценариями при конкретном дефекте. |
| `inter-vlan.html` | Пошаговые SVI/обратный путь, отдельные диагностики. Частично перекрывается нынешними VLAN/CLI; оценить только недостающий учебный шаг, не создавать третий стенд вокруг тех же событий. |
| `dhcp.html` | Пособие DORA с режимами и ошибками. Сравнить с `dhcp`/`dhcp-lease` по покрытию; не переносить второй DORA и не объявлять поддержку relay/renew, которых страница не моделирует. |
| `nat-pat.html` | Полезный пример двух клиентов с одним внешним адресом/конфликтом порта, которого недостаточно видно из линейного NAT-стенда. Кандидат для отдельной адаптации после приёмки, не готовая замена. |
| `dns-tcp.html` | Сильный недостающий переход «имя → адрес → соединение»; это сценка, не авторитетный DNS-сервер или настоящий TCP-захват. Кандидат после проверки границ модели. |
| `wireshark.html` | Отдельная историческая визуальная практика чтения пакета; пробел относительно интерактивов текущего каталога. Не подменять ей реальный pcap/дамп; проверить корпус примеров и лицензии перед переиспользованием. |
| `ipv4.html`, `ipv6.html` | Дубли основного назначения современных тренажёров. Переносить только подтверждённые недостающие виды упражнения, после проверки на дубликаты и сопоставления ID. |
| `cli/`, `cli/read.html` | Старые каталог/практика чтения вывода и ремонта, есть отдельные файлы Eltex, H3C, MikroTik, Siemens/SCALANCE, Huawei, Moxa. Оценивать как источники для будущего справочника; не считать эти текстовые упражнения готовыми вендорными engine-модулями CLI Lab 2.0. |


## Выборочная проверка настоящего входа

Chromium использовал **локальные сборки закреплённых архивов**, а не мок-компоненты: 375×667 и 1440×900 для каждого текущего снимка. В обоих открылись главный экран тестов, шпаргалки L1–L7, сценарии, урок ARP из каталога, Packet Journey (ползунок показал ARP `192.168.1.10 → 192.168.1.1`), «Дело 4» в VLAN, три вкладки DHCP/NAT/PAT/TCP, реальная CLI-сцена «Access VLAN на порту», IPv4 и тренировка IPv6. Отдельно открыта и закрыта визуальная ARP-сцена только в staging; по меню подтверждено, что макеты есть лишь в staging. Не переобозначаем этот smoke как проверку каждого сценария.

На историческом исходнике Chromium 375×667 открыл главную, 6 сценок (`packet-journey`, `vlan-trunk`, `inter-vlan`, `dhcp`, `dns-tcp`, `nat-pat`), оба адресных тренажёра, Wireshark и оба входа CLI; во всех шести сценках сработал первый шаг. Это проверка доступности закреплённых страниц без ошибок JavaScript, а не независимая приёмка механики, вывода CLI или полного сценария. Битых входов в этой выборке не найдено; неприменимые, отсутствующие и непроверенные перечислены отдельно.

## Что говорят числа будущих итогов

В обоих снимках 8/12 курсов набирают 20 **по формальным квотам укрупнённых корзин**, а не по всем учебным навыкам; `family` в банке не идентификатор навыка. У четырёх дефицит уже на этом шаге: введение −8, транспорт/UDP −2, защита −5, промышленность −10. В пилоте IP-адресации 5/9/6 слотов, включая локальные сценарии IPv6; запись/сжатие IPv6 остаётся практикой, но вне оценки пилота. PoE-расчёт и проверка настройки trunk/SVI требуют отдельной содержательной сверки, хотя их курсы прошли формальные квоты. ## Воспроизводимость и ограничения

`npm run build` в обоих SHA. Для реестров можно бандлить `scripts/in-depth-entry.ts` существующим `bundleEntry` из `scripts/load-bank.mjs`; статус личной приёмки брать из `src/data/lessons/reviewStatus.ts`. Для квот см. метод отбора в [архитектуре](NETOPS_COURSES_ARCHITECTURE.md#карта-и-итог-20). Статический осмотр маршрута не подтверждает успешное решение каждого уровня CLI, все крайние случаи симулятора, смысл всех 860/861 разборов, лицензии исторических материалов, байтовое соответствие текущего CDN или работу аккаунтов, которых в снимках нет. Ни один курс, новая визуальная система или historical-модуль этим актом не принимается.
