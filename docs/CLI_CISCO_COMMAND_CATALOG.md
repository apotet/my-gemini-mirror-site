# Cisco IOS CLI Lab: единый каталог команд

## Источник истины

- Исполняемые команды: `src/cli-lab/vendors/cisco-ios/commands.ts` и импортированные обработчики `l3Commands.ts`, `trunkCommands.ts`, `showInterfaceCommands.ts`, `persistenceCommands.ts`.
- **Единый каталог:** `src/cli-lab/vendors/cisco-ios/commandCatalog.ts` — формируется из `ciscoIosCommands` (реально исполняемых `CommandSpec`) и обогащает записи описанием, режимом, категориями, тематическими метками.
- Сценарии: `src/cli-lab/scenarios/*.ts`, их `concepts` — только источник учебных рекомендаций, не разрешения на выполнение.
- Проверка: `scripts/cli-command-catalog.test.mjs`.

## Основной принцип

**Включённые в движок диагностические команды доступны во всех сценариях**, если CLI-режим и уровень привилегий подходят. Сценарий определяет исходное состояние и цели, а не собственный урезанный список команд. `commandCatalogForScenario(scenario)` возвращает рекомендуемые команды, прочую диагностику и остальные команды; ничего не скрывает.

Режимы `LEARN / DRILL / TASK` не меняют доступность команд, а уровни `BASE / APPLIED / ADVANCED` задают сложность задач.

## Не путать каталог с полной справкой Cisco

«Все Cisco-команды» как единый универсальный список технически некорректны: IOS, IOS XE, NX-OS, модели и версии отличаются. Реестр помечает только реально исполняемые обработчики CLI Lab. Неизвестные или ещё не эмулированные команды не должны возвращать выдуманный вывод. Для будущей справки можно вести отдельный **документированный, но не исполняемый** список с моделью, версией, ссылкой на официальный источник, статусом реализации и условиями поддержки.

## Правило добавления команды

1. Выбрать документированный диалект и устройство Cisco.
2. Реализовать парсинг, mode/privilege, изменения состояния или диагностический read-only вывод.
3. Зарегистрировать `CommandSpec` в общем `ciscoIosCommands`.
4. Добавить метаданные в `commandCatalog.ts` (категория, темы, описание).
5. Тестами проверить положительный/отрицательный сценарии, влияние на другие устройства и обратную совместимость.
6. В интерфейсе показывать «Рекомендовано для этого сценария» отдельно от «Вся доступная диагностика».

Это первый технический этап. UX-каталог Grok сможет читать через `commandCatalogForScenario` без копирования конфигурационных команд в React-компоненты.
