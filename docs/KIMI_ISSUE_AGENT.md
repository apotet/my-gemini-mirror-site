# Химик — Kimi Agent v2

Единый runtime: [AGENT_RUNTIME.md](AGENT_RUNTIME.md).

Префикс `[KIMI]`, существующий секрет `MOONSHOT_API_KEY`, default model `kimi-k3.1-pro`.
Issue от владельца с JSON-заданием **не запускает модель при создании**. Для запуска
владелец пишет точный комментарий `/agent start confirm-paid-api`. Ручной workflow
требует явного `confirm_paid_api=true`. Платный API, не подписка Coding Plan.

В задаче `budget_usd` по умолчанию `"0.75"` (диапазон $0.01–$2.00), общий дневной
лимит расчётных резервов — $2.00 по UTC. `max_calls` — начальный grant (по умолчанию 8),
`max_total_calls` — максимум на задачу включая продолжения (по умолчанию 24, максимум 32).
`max_output_tokens` (по умолчанию 16384, максимум 65536) передаётся API;
`max_input_tokens` (по умолчанию 120000, максимум 250000) ограничивает **оценку** входа.
Продолжение требует комментария владельца с точным checkpoint и числом новых вызовов.
`calls: 0` не разрешает обращений к модели. Старые Kimi checkpoints без лимитов
нельзя продолжить платным вызовом.

Владелец может явно изменить лимиты при продолжении существующего checkpoint:

```text
/agent continue {"checkpoint":"<актуальный SHA>","calls":1,"limits":{"max_total_calls":32,"max_output_tokens":16384,"budget_usd":"0.75"}}
```

`limits` допускает только `max_total_calls`, `max_output_tokens`, `max_input_tokens`
и `budget_usd` с теми же диапазонами, что у новой задачи; указываются только нужные
поля. Прежний бюджет не увеличивается автоматически: изменение `budget_usd` должно
быть явным. Ранее учтённые расходы и частичный ответ сохраняются, как и модель,
ветка и область записи. Суточный лимит остаётся $2.00. Даже при увеличенных лимитах
задача может приостановиться из-за бюджета или другой ошибки: продолжение не гарантирует
завершения. Изменения фиксируются в checkpoint, а новый платный вызов требует отдельного
разрешения owner-комментарием или подтверждённым ручным dispatch; автоматического повтора нет.

Перед вызовом вход оценивается как половина длины сериализованного запроса в UTF-8
плюс 256 токенов на сообщение; это эвристика, не токенизатор, и она может занижать
реальное число токенов (особенно для изображений). Стоимость рассчитывается по
известным тарифам с верхней ставкой записи кэша и полным лимитом выхода. До вызова
оценка резервируется в общем Git-ledger за UTC-день; параллельные обновления
защищены CAS. После ответа учитывается верхняя граница фактической стоимости по
usage; при неизвестном расходе или сбое резерв сохраняется. Сбой после резервирования
также может оставить резерв до конца суток. Неопределённый запрос не повторяется
автоматически. Отчёт Issue содержит usage, оценку, лимиты и неизвестные суммы.

Это **не гарантированный денежный потолок**: реальные токены, тарифы, налоги и
провайдер могут отличаться от расчёта. Дневной ledger охватывает только этот runtime,
не другие клиенты Moonshot; баланс и счёт сверяет владелец. По умолчанию защищены
runtime и секреты, кандидат проверяется в sandbox, публикуется только в `kimi/*`
и Draft PR. Независимую проверку выполняет другой агент; merge и deploy запрещены.
Старые Kimi-задачи сохраняют прежние ветки и checkpoints.
