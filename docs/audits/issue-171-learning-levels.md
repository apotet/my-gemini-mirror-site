## Шкала и контракт

Центральный тип `LearningLevel = 1 | 2 | 3 | 4 | 5` и русские/английские названия находятся в `src/types/learningLevel.ts`:

| Уровень | Название | Критерий аудита |
|---|---|---|
| 1 | Основы / Fundamentals | Назвать, распознать, вспомнить формат или назначение |
| 2 | Понимание / Understanding | Объяснить одну простую связь |
| 3 | Применение / Application | Выполнить расчёт, прочитать таблицу/дамп, выбрать настройку |
| 4 | Диагностика / Troubleshooting | Сопоставить наблюдения и спланировать проверку причин |
| 5 | Эксперт / Expert | Совместить несколько механизмов и существенные условия их взаимодействия |

`getLearningLevelMetadata(id)` возвращает размеченное объединение:

- `status: "ASSIGNED"` с `learningLevel`, историческим `auditAction` KEEP/RELABEL, confidence и дословным auditRationale.
- `status: "REVIEW"` **без learningLevel**, с историческим `auditProposedLevel`, результатом последующих PR и причиной ручной проверки.

Неизвестный ID вызывает ошибку; значения difficulty не используются как fallback. Потребитель обязан отдельно обработать REVIEW. Реестр проверяется на совпадение с полным банком при импорте модуля. Записи и объект реестра заморожены. Существующее приложение этот модуль не импортирует: классификация пока используется только самостоятельной валидацией/тестами.

Старые `Question.difficulty` (`basic|beginner|intermediate|applied|advanced`) и `QuizSession.difficulty` (`beginner|mixed`) полностью сохранены. RELABEL означает перенос аудиторского предложения в **новый реестр**, а не замену старого difficulty.

## Воспроизводимые проверки

```sh
npm run validate:learning-levels
npm run test:learning-levels
npm run lint
npm run build
npm run test:logic
npm run coverage:explanations
git diff --check
```

`validate:learning-levels` включён в prebuild, поэтому пропущенный ID или неверная запись останавливают сборку. Реестр хранится по одной записи ID на строку; проверка исходного JSON отдельно обнаруживает дубли ключей, которые обычный JSON.parse скрыл бы.

`issue-171-baseline.json` фиксирует SHA256 всей последовательности вопросов, проекции опубликованного аудита и существовавших 168 файлов src. Это граница проверки этапа 2, не новый источник классификации. Для будущего согласованного изменения содержимого/логики baseline следует обновлять осознанно вместе с соответствующей миграцией; обходить проверку fallback-уровнем нельзя.

Целевые тесты проверяют:

- Все 787 ID, 347/426/14, уровни 1–5, точные статистики и дословный перенос action/level/confidence/rationale из опубликованного CSV через fingerprint.
- Отказ при пропущенном, лишнем или дублирующемся ID банка, недопустимом уровне/статусе, неполном REVIEW и попытке назначить REVIEW уровень.
- Неизменность всего банка и порядка, ключей, difficulty, существующих селекторов, UI, типов и восстановления сессий.
- Все 8 режимов, оба старых difficulty и размеры 1/5/10/15/20/30: прежние пулы и воспроизводимые выборки; legacy beginner содержит 244 вопроса и не исключает новые Application.
- Шесть вариантов старых сессий: без difficulty, beginner и mixed, каждый с answerOrders и без него; сохраняются ID, порядок ответов, текущая позиция, подтверждения, attemptId/progressEpoch и исходные поля requestedCount. Включены REVIEW и повторы family, допустимые в старых попытках. Новая разметка не перефильтровывает и не пересоздаёт сессию.

Существующие mixed/10 quota/family/template/error-path тесты также запускаются через test:logic. CustomQuestions и повторение ошибок продолжают существовать без изменений исходного кода.

Результаты локального запуска: lint (tsc --noEmit), build с prebuild, test:logic, coverage:explanations, test:learning-levels и diff check — PASS. Все 51 отдельных scripts/*.test.mjs: 45 PASS, 6 FAIL; новых падений нет. Шесть воспроизведены на чистом main того же SHA: answer-shuffle (dynamic require React в ESM), cli-experimental-topology (отсутствующий жёстко заданный resolveDir), cli-reference (6 ожидаемых уроков против 8), glossary (FIN), practice-links (l2-07), study-text (набор ID). В этой задаче они не исправлялись.

Все 7 выходных файлов сборки dist, включая HTML/JS/CSS, побайтно совпали с чистым main. Локально использован Node 24.22.1; это не заявление об успешном GitHub CI. Сборка сообщает прежнее предупреждение Vite о крупных chunks; coverage показывает прежние пробелы индивидуальных разборов. Подробности также приведены в описании PR по Issue #171. Merge/deploy и изменение production apotet/netops в этот этап не входят.
