## Чего действительно не хватает для общего PASS

1. **Законченного решения о переносе заключений, а не ещё одного полного аудита.** В этой работе техническая по-ID/по-компонентам карта уже построена: фактический resolver 188c для 149 ID + сохранённые payloads #334 для 11 дают **160/160 точных исторических hash** против неизменённого ledger. Для каждого текущего ID записаны изменённые поля question/deep/точной целевой секции. Однако к каждому принятому изменению ещё нужно привязать имеющееся смысловое заключение, а не выводить его из технического восстановления. Единого исторического Git-снимка эта составная проверка не доказывает.
2. **Область за пределами адресных 9+2 нельзя незаметно считать закрытой.** В приложенном индексе 153 остальных ID: у 43 есть дополнительные ссылки в просмотренных структурированных Grok JSON и отчёте семи маршрутов, у 110 в этом ограниченном наборе таких ссылок нет. Другие записи ROADMAP (в том числе Gemini Work Batch03 на 835a2e09), PR-комментарии и внешние архивы этим числом не опровергаются; их исходные результаты ещё требуется включить в версионную связку. Это **не 110 непроверенных вопросов и не 110 FIX**: у них есть исторические чтения. Числа показывают, где сначала переиспользовать имеющееся доказательство и проверить версионный перенос. Наличие поздней ссылки также не доказывает полного совпадения текущего материала.
3. **Четыре ID вне старого ledger:** l3-d05/l4-d05 входят в семь маршрутов Gemini; l4-d03/tcpip-d05 в этом наборе отдельной поздней рецензией не покрыты. Для них сначала найти существующее предметное заключение и сопоставить исходник/поле; только при реальном пробеле назначать адресное чтение. Не отправлять все 164 на повторный аудит.
4. **Явное согласование строгой политики с ограниченным closeout.** Текущий `in-depth-review-policy.mjs` признаёт лишь старую status=PASS с тем же полным hash и намеренно не использует новые Markdown PASS. Поэтому принятие 9+2 не может само переключить GATE-06. Нельзя объявить блокер снятым только записью PASS в ROADMAP. Решение должно сохранять исторические ledger/baselines и доказать перенос существующих заключений на текущую версию; сейчас такой законченной связки нет.
