### IPv6 / `review-slaac-4` — SOURCE PASS

- Условие из `src/data/questions.json`: Ethernet, RA PIO `2001:db8:120::/64`, `A=1`, Valid 3600 с, Preferred 1800 с, SLAAC разрешён. Верный ключ — вариант 0: хост строит полный адрес из префикса и собственного IID, затем выполняет DAD.
- Три неверных варианта предметно отвергнуты: адрес отправителя RA принадлежит маршрутизатору; Neighbor Advertisement не выдаёт клиенту готовый адрес; один адрес сети без выбранного IID не описывает SLAAC.
- `src/data/questionExplanationsApplied.ts` содержит индивидуальные `brief/plain/pro/trap`; в обоих стилях правильно отделены PIO A, DAD, IID (не обязательно MAC), сроки Preferred/Valid. `src/data/inDepth/group3.ts` содержит подходящий `practicalTip` и точный `l3-ipv6#in-depth-slaac-ra-address-formation` в обоих режимах, с различением A/L и Router Lifetime.
- **Новый подтверждённый контекстный дефект:** до исправления общий glossary matcher воспринимал одиночную `A` в SLAAC `A=1` как DNS A-запись. Исправлено `ipv6`-scope только для `l3-ipv6`, добавлены точные подсказки `A=1`, `A=0`, `L=1`, `L=0`, `A/L`, сохранено значение настоящего DNS A. См. новый регрессионный тест в `scripts/in-depth-content.test.mjs`. Значения для других уроков не меняются.

### RSTP / `stp-new-04` — SOURCE PASS

- Условие из `src/data/questions.json`: P1 Root/Forwarding физически down, исправный P2 Alternate/Discarding имеет свежую информацию о прежнем корне; оба соединения point-to-point, прочие порты operational edge, защитных конфликтов нет. Правильный ключ — вариант 0: P2 получает роль Root, rapid transition возможен без ожидания Max Age на **физически отключённом** P1.
- Три неверных варианта отвергнуты адресно: ожидание Max Age ошибочно для обнаруженного физического link down; S не становится корнем при наличии рабочего пути; P2 — Root, а не Designated.
- `src/data/questionExplanationsApplied.ts` даёт три различимых уровня объяснений; `src/data/inDepth/group4.ts` связывает билет с `l2-rstp-convergence#indepth-rstp-root-failure` в обоих режимах. Материал предупреждает, что время сходимости в иных топологиях не гарантировано.
- **Уточнение по командам:** `show spanning-tree detail` в `practicalTip` ограничено поддерживаемыми Cisco IOS/IOS XE; для других устройств указана штатная RSTP/BPDU диагностика. Не превращать Cisco CLI в универсальный протокол.

**Ограничение:** тесты по коду подтверждают реальные ключи, заполненные два режима и точные ссылки; только Chromium/пользовательская проверка подтверждают popup, навигацию, состояние экрана и фактическую доступность целевого блока.
