### Confirmed shared-context defects and minimal repair scope

1. The plain Trap/Inform section says `предварительный Get`, which the actual case-insensitive tokenizer resolves as HTTP GET. Its professional counterpart uses `request-id` and `retransmission`, yielding DHCP Request and TCP byte-retransmission tooltips. Those generic definitions are not wrong in their own domains. Replace the local phrases with `запрос чтения SNMP`, `идентификатор запроса SNMP` and `повторные отправки`; do not redefine HTTP, DHCP or TCP globally.
2. The professional command title promises `UTC msec`, while `service timestamps log datetime msec show-timezone` only formats timestamps and displays the configured zone. It does not establish UTC or synchronize time. Remove UTC from the title; the existing lesson explicitly explains NTP, zone interpretation and that chronology alone does not prove causality.
3. In the Zabbix pack, active-agent labels/prose select BGP `Active`, `nodata` selects DNS NODATA, and `update interval` selects BGP UPDATE. Use explicit Zabbix phrase definitions/aliases and localized prose; preserve the real item-type answer `Zabbix agent (active)` and the unrelated protocol definitions.
4. SNMP01 and Syslog01 initial practical tips exactly duplicate their memorization-rule fields. Preserve those memory rules and supply direct operations: compare agent/manager authPriv/algorithm settings and inspect a permitted snmpget, and compare a missing event's severity with the configured IOS threshold.

## Primary references actually checked

- [RFC3414 §1.4 and §2](https://www.rfc-editor.org/rfc/rfc3414): authentication/integrity versus confidentiality, engine identity and time-window mechanisms. The fetched text explicitly states that confidentiality is not provided without data integrity and data-origin authentication.
- [RFC3826](https://www.rfc-editor.org/rfc/rfc3826): AES privacy protocol is CFB with 128-bit key; higher AES variants require matching implementation support rather than being implied by `authPriv`.
- [RFC3416](https://www.rfc-editor.org/rfc/rfc3416): confirmed InformRequest versus unconfirmed SNMPv2-Trap PDUs, request identifiers and application-level response/retry semantics. Polling cannot recreate every intermediate event.
- [RFC5424 §6.2.1](https://www.rfc-editor.org/rfc/rfc5424#section-6.2.1): severity 0–7 and PRI = facility × 8 + severity; 165 = local4/notice.
- [Zabbix agent parameters](https://www.zabbix.com/documentation/current/en/manual/appendix/config/zabbix_agentd): StartAgents=0 disables passive listeners in agentd.
- [Zabbix agent2 parameters](https://www.zabbix.com/documentation/current/en/manual/appendix/config/zabbix_agent2): omission of Server disables passive checks; no StartAgents setting. These exact official pages survive in the inspected local HTML cache; the relevant Server/StartAgents passages were read.

GetBulk's dictionary wording mentioning SNMPv2c is true but not exhaustive: the same PDU family is also usable with v3. It does not say “only v2c,” and the lesson does not assert that v3 lacks bulk operations; this is not classified as a new blocking defect. The counter widths, time-to-wrap examples, hysteresis versus temporal window, dependency limitations and heartbeat/nodata caveats were also read and are technically consistent.
