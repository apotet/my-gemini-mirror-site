## Зачем мы делаем «Углублённый»

Цель — не просто получить зелёный CI и ссылку из каждого вопроса, а создать учебный уровень, который **обучает сетевым технологиям**. Ученик после разбора и связанного урока должен понимать, почему правильный ответ верен, почему альтернативы неверны, как работает механизм и где применять знания. Простой режим должен быть понятен новичку; инженерный — давать техническую глубину и диагностическую логику.

Уровень закрывается по согласованному стандарту качества, близкому к тщательно проработанному уроку PoE `l1-poe-budget`. Это ориентир глубины, **не утверждение, что PoE уже окончательно принят владельцем**.

## Критерии для каждого из 164 вопросов

1. Корректное условие, четыре осмысленных варианта, один обоснованный ключ; дистракторы проверяют понимание, а не угадывание.
2. Индивидуальное объяснение «Почему так» и понятный слой «Простыми словами», согласованные с условием и ключом.
3. Предметный слой «По делу»: механизм, границы применимости, практические инженерные нюансы, проверка и типичные ошибки; без шаблонных советов не по теме.
4. **Рабочая ссылка на релевантный урок и точную тематическую секцию**; раздел реально объясняет ответ в обоих стилях, а не просто содержит похожие слова.
5. Контекстные подсказки для нужных терминов; корректные сокращения и различие стандартов, протоколов и вендорских особенностей.
6. Реальная практика/кейс или тренажёр там, где это педагогически оправдано; не придумывать фиктивную практику ради галочки.
7. Проверенная навигация «вопрос → урок → нужный раздел → назад», мобильный/десктопный интерфейс, переключение стилей.
8. Сохранность старых попыток, вариантов, ключей и результатов; изменения учебного текста не должны ломать историю.
9. Независимая содержательная проверка изменённых мест и сложных маршрутов; повторно не аудировать неизменённый уже принятый материал.

**Важно:** несколько вопросов вправе вести в один урок, но в разные тематические разделы. Число вопросов не равно числу отдельных уроков. Приёмка вопроса/маршрута не равна личному утверждению всего урока владельцем.

## Текущее состояние GATE-06

- **Структура/навигация:** все **164 вопроса × 2 ширины = 328** браузерных маршрутов прошли Chromium на коде `9b1397b`. Проверены переход в урок, тематический якорь, оба стиля и возврат; это **не** доказательство педагогического качества каждого урока.
- **CI:** семь выполненных проверок SUCCESS; два условно пропущенных задания не считаются PASS.
- **Историческая совместимость:** PASS в проверяемой области, включая сохранённые варианты/ответы/результаты; не заявляется чтение личного localStorage владельца.
- **Содержательная приёмка:** **9 полных пакетов + 2 ограниченные дельты — PASS**, 33/33 компонентных хеша совпали с принятым источником. Остальные **153 ID** требуют завершения доказательного сопоставления уже существующих рецензий с текущими изменениями, а не автоматического нового аудита.
- В инвентаризации: 10 полностью идентичных историческому материалу, 43 с изменением только общего контекста, 107 с прямыми компонентными дельтами и 4 новых относительно старого ledger. Это классы **изменений**, не число ошибок.
- Повторный PASS Batch03 уже обнаружен; не проверять его повторно без выявленной новой смысловой дельты.
- **Общий GATE-06 = BLOCK; L2 CONTENT ACCEPTED = NO.** Причина — незавершённая связка «конкретное изменение → действующее независимое заключение» для остального объёма. **Не утверждается**, что все уроки плохие или что 153 вопроса имеют ошибки.
- Merge и публикация не выполнены. Production `apotet/netops` не менять без отдельного разрешения.

## Следующее действие без расширения объёма

Сопоставить существующие рецензии (включая Gemini Work Batch03, PR-комментарии, Grok и уже принятые адресные рецензии) с картой точных компонентных изменений из [индекса доказательств](gate06-evidence-reconciliation-20261124.json). Для каждой дельты установить: прежний PASS применим / применим частично / отсутствует актуальное заключение. Только реальные пробелы отдавать на адресную предметную проверку; обнаруженные FIX исправлять и повторно проверять. После доказательного общего PASS обновить ROADMAP, выполнить разрешённые релизные этапы и smoke; **не публиковать на основании одного зелёного CI**.
