## Исправления

- `TheoryRazbory`: «Почему так» всегда использует `briefAnswer`, независимо от выбранного подробного стиля. В «Подробном разборе» простой текст берётся из `deepAnalysis`, профессиональный — только из непустого `professional.deep`. Общий текст не объявляется профессиональным материалом. При отсутствии pro показано предусмотренное стандартом сообщение, переключателя нет.
- `ExplanationLesson` в `EngineeringReview.tsx` используется в обоих компонентах. Он разрешает реальный урок из действующего реестра, показывает название и вызывает обработчик с `(lesson.id, questionId)`. Без урока показано предусмотренное сообщение. В теории ссылка доступна и при свёрнутом подробном разборе.
- Сохранены варианты, изображения, типичная ошибка, практика, памятки и словарные подсказки теории. Тексты банка/объяснений, ключи, уровни, форматтер PR #228 и сериализация попыток не менялись. В защитном baseline обновлён только fingerprint изменённого `TheoryRazbory`; предыдущие разрешённые изменения навигации PR сохранены.
- Актуальная формулировка GATE-10 получена из main: обычному staging-merge не требуется отдельное разрешение на каждую галочку. Это не отменяет независимую приёмку и явный запрет merge в текущем задании.

## Проверки и доказательства

- `npm run lint` выполняет TypeScript typecheck (`tsc --noEmit`). `npm run build` включает проверки банка, связей и защищённого baseline.
- `npm run test:logic` проверяет режимы, восстановление, сохранённые снимки, статистику и отсутствие повторного учёта при просмотре. `npm run test:explanations` сохраняет регрессии форматтера и содержания.
- `npm run test:review-navigation`: оба компонента по всем 862 вопросам; наличие/отсутствие материалов и переключателя; фактический вызов `onClick` общей кнопки с проверкой двух аргументов для каждого связанного вопроса; дополнительно шесть явных эталонных соответствий из таблицы.
- `scripts/explanations.browser.mjs`: существующие CLI/форматирование, словарь, IPv4/IPv6-практика, навигация и старые попытки.
- `scripts/review-materials.browser.mjs`: 6 вопросов × 7 сценариев × 2 ширины = **84 проверки**. Сценарии: `last-attempt`, `instant`, `theory`, `final-result`, `mistakes`, `mock-instant`, `mock-result`; ширины 375/1440 px. В каждом проверяются короткий текст, реальное переключение, честное отсутствие материалов, переход к ожидаемому уроку и исходному вопросу, отсутствие горизонтального переполнения. Для повторения ошибок явно выбирается смешанный уровень.
- Начальное предпочтение в матрице — pro: вопросы без pro не должны создавать фиктивный профессиональный слой. Историческая завершённая попытка содержит собственное сохранённое пояснение; при просмотре и навигации её JSON остаётся byte-identical. Новое завершение законно заменяет последнюю попытку, после чего новый снимок также защищён от изменений просмотром.

В GitHub Actions шаги `Review lesson links and missing materials` и `Responsive explanation flows` выполняют эти тесты. Артефакт **bank-coverage** содержит:

- `matrix-evidence.json` — запись каждой из 84 проверок с ID, шириной, наличием материалов и именами снимков;
- `{surface}-{questionId}-{width}.png` — разбор соответствующего сценария;
- `lesson-{surface}-{questionId}-{width}.png` — открытый урок, включая название и возврат к исходному вопросу;
- `review-material-coverage.json` — полный список пробелов учебного покрытия.

Дополнительно локально собран main указанного SHA и просмотрены `ts-x12`/`l57-d02` на обеих ширинах. Подтверждены исходные дефекты: отсутствие сообщений и смена краткого ответа TLS при выборе pro. Сохранение вспомогательных блоков проверено в сравнении с main. Эти локальные снимки не выдаются за CI-артефакты.
