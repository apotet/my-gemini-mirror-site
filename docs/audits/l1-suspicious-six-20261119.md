## Замечания первой независимой проверки — исправления подтверждены

1. **ИСПРАВЛЕНО / исходный BLOCK `l1v2-a-poe-limit`**. Условие спрашивает точные `PSE Type/Positive/Negative` с экрана; действующий `ADVANCED_INDIVIDUAL_DEEP` в `questionExplanations.ts` вместо этого в `brief` и `deep` говорит главным образом, что **54,6 В и Class 0 не доказывают 60 Вт**. Это полезное дополнительное примечание, но не ответ на заданное условие. Переделать индивидуальные `brief/plain/pro/trap` с верным считыванием, затем вторым планом объяснять ограничения интерпретации Class 0/потребляемой мощности.
2. **ИСПРАВЛЕНО / исходный BLOCK `l1v2-c-otdr-pulse`**. Условие спрашивает **буквально указанную длительность 100 ns**, а действующий `brief` утверждает необходимость укоротить импульс, `deep` начинается «Уменьшить длительность импульса». Выбор/компромисс OTDR не задан; разбор нужно переписать под наблюдение 100 ns и отдельно дать техническую справку о разрешении/динамическом диапазоне.
3. **ИСПРАВЛЕНО / исходный REVIEW `l4-d03`**: текущий `brief/deep` краткий, `deep` содержит смешение языков («incarnции», «reliability RFC793 FSM»); независимо оценить соответствие требуемым «Простыми словами»/«По делу». Не выдавать два предложения за полноценно проверенные стили.
4. **ИСПРАВЛЕНО / auditRationale registry**: у четырёх перенесённых записей `auditRationale` дословно осталось «Распознать ...», без объяснения нового порога знаний L2. Зафиксировать предметный аргумент в утверждённой метаинформации и обновить `auditProjectionSHA256` только по реальному `validate-learning-levels`, а не переписывать контрольные значения наугад.
5. **ИСПРАВЛЕНО / CI-тесты**: исходная ветка Grok не обновила `scripts/base-level.browser.mjs`, `scripts/learning-level-exam.test.mjs`, `scripts/foundation-lessons.test.mjs`, `scripts/photo-review.test.mjs`, `scripts/applied-l3-session-batch1.test.mjs` после смены уровней. Ревизор исправил ожидаемые счётчики, сохранив старую фото-матрицу хеширования и разрешив **только** эти 4 именованных изменения. Не отключать проверки; финальный CI должен быть PASS.
6. **Привязка уроков и фото**: сами `question`, `answers`, `correct`, `image`, исходные уроки и сохранённые попытки не изменялись. До приёмки следует проверить реальный resolver и оба вида разбора шести ID, читаемость двух фото на 375 px и восстановление старых L1-сессий, в которых эти 4 вопроса уже были показаны.

## Результат второй независимой смысловой приёмки

**PASS по шести билетам** (повторное чтение кода и live bank на SHA `05a00a1145a5e664a5d9e919c64bdec5872eff0f`): PoE PSE Type / полярность `Positive 3,6; Negative 1,2` в обоих объяснениях; OTDR ровно `100 ns` без выдуманной смены импульса; TIME-WAIT корректно объясняет 2MSL; четыре точных перемещения L1→L2; исходные условия/ответы/фото и PR #253 не менялись. Технический совет для будущей шлифовки: объяснение TIME-WAIT можно уточнить словами «получает FIN соседа, отправляет последний ACK, входит в TIME-WAIT»; текущий текст не считается блокирующей технической ошибкой.

Последующий CI обнаруживал устаревшие защитные фикстуры; историческую photo-review матрицу восстановили **только для четырёх поимённо проверенных изменений**, не отключая SHA-защиту. Добавлен прямой регрессионный тест шести конкретных ID: правильный ключ, `brief/plain/pro`, реальный урок, отсутствие четырёх L2 в новой Base, восстановление старой Base-попытки с этими ID. Итоговый CI и обязательные 10 gates должны пройти на финальном коммите; утверждать публикацию только после Pages/live smoke.
