# Gemini Designer: отдельный мультимодальный контур

Основание: [решение владельца в #563](https://github.com/apotet/my-gemini-mirror-site/issues/563#issuecomment-7236134353). Этот код не включает запуск. Константа `DESIGNER_TRANSPORT_RELEASED=False` не изменяет старые `[GEMINI DEV]`, audit-only `[GEMINI]` или `[HYDROGEN DEV]`, workflow, права, секреты и лимиты. Здесь нет обработчика Issue, правок продукта, инструментов модели или автоматического применения рекомендаций. Production не затрагивается.

## Что требуется до первого вызова

1. Владелец `apotet` подтверждает существующий **совместимый ключ именно выбранного Google Cloud/AI Studio проекта**. Не копировать значение в чат, Issue, отчёт, shell history, аргументы команды или артефакты. Хранимое имя `GEMINI_API_KEY` в существующем action не доказывает, что секрет задан, не просрочен и принадлежит проекту. Для выбранного runner ключ должен допускать Generative Language API (ограничение по сервису и подходящая политика egress); не требуются редакторские IAM-права Google для самого вызова. Для просмотра тарифа/условий достаточно доверенному оператору иметь доступ к Billing, Usage и настройкам проекта; создание/смена ключей и увеличение лимитов не входят в работу.
2. Действительный штатный диагностический вызов: `GET https://generativelanguage.googleapis.com/v1beta/models?pageSize=50`, затем `pageToken` из `nextPageToken` до конца. Передавать секрет только в HTTP-заголовке `x-goog-api-key`. Существующий owner-only `.github/workflows/gemini-list-models.yml` (`workflow_dispatch`, actor=`apotet`) вызывает `scripts/gemini-list-models.py`, не генерацию. Его артефакт хранит имена и методы, но **не** `inputTokenLimit` / `outputTokenLimit`; их нужно снять из ответа API или `GET /v1beta/models/<точный-id>` тем же ключом. Для выбранной модели подтвердить в этом проекте `countTokens` и `generateContent`, поддержку изображений, JSON-ответа и отдельный верхний предел оплачиваемого reasoning. Успех List Models не гарантирует, что генерация реально доступна; проверять только в отдельном принятом ARP-пилоте. Если у проекта доступен только Interactions, не подменять его REST-методом и не включать fallback.
3. Для того же проекта сверить фактический тариф и квоту: тип оплаты/уровень, действующие RPM/TPM/RPD, верхние цены стандартной нестриминговой text/image input и visible+thinking output, максимальную стоимость `countTokens`, наличие уже согласованного внешнего стопа расходов и условия передачи/хранения данных. Не считать подписку Gemini в приложении кредитом Developer API. Не подставлять цену по названию модели или автоматически принимать рекламу free tier. Внешний проектный spend cap и внутренние предварительные резервы не равны гарантии счета: Google предупреждает о задержке применения проектного ограничения. Учитывать общий расход проекта другими клиентами, который этот ledger не контролирует.
4. Независимо проверить сами доказательства модели, тарифа, data terms и стопа, затем утвердить их хеши. Проверка формы SHA-256 в коде проверяет только синтаксис и закрепляет профиль: она не подтверждает существование или настройки проекта, подлинность доказательств и связь ключа с проектом. Составить доверенный профиль `netops-gemini-designer-profile-v1` (точные поля в `designer.PROFILE_FIELDS`), с коротким сроком действия `expires_utc`. `project_binding` — неизменяемый SHA-256 идентификатор проверенного проекта, одинаковый для всех его задач и итераций; это не хеш ключа. `native_*` идут из метаданных выбранной модели. `round_output_tokens` задаётся проверенным нативным пределом и выделением бюджета; код не навязывает маленький лимит вывода. `max_billed_thought_tokens` покрывает отдельно оплаченные размышления (ноль только если проверено). Параметр запроса `maxOutputTokens` сам по себе не доказывает отдельно оплачиваемый предел reasoning: если выбранная модель не даёт проверяемой верхней границы, запуск остаётся выключен. Деньги `*_micro_usd` и `count_request_max_micro` — целые миллионные доли USD, ставки — десятичные строки USD/1M токенов. Использовать верхние ставки для всех применимых уровней цены и типов входа, а не оптимистичную цену для кеша. Предел полного inline-запроса до 20 000 000 байт с JSON/Base64; большие файлы не отправляются по ссылке и не переносятся в Files API. Границы файлов, суммарных пикселей и таймаут утверждаются в профиле; для визуального пилота не уменьшаются произвольно.
5. Независимо принять код, готовность доверенного runner (Linux с проверенной версией Pillow и выходом к двум утверждённым API) и доступ к отдельному нефорсируемому accounting ref `agents/budgets/gemini-designer-global`. GitHub-креденшал подаётся только доверенному запуску под именем `GH_TOKEN`, нужен доступ Git Data для чтения и создания/fast-forward служебного ref; не нужны PR/Issues/Actions write, секреты проекта или production. Если существующая политика не позволяет записи CAS, остановиться, не расширять права автоматически. После отдельного разрешения выпустить только новый gate и защищённую точку запуска. Эта будущая точка должна закрепить проверенный SHA доверенной ветки main (не код PR или рабочей копии), выбранный ключ и его проект, хеш утверждённого профиля, хеш отдельно просмотренного медиапакета и подтверждённую верхнюю границу оплачиваемого reasoning для модели. Несовпадение или непроверенное значение блокирует запуск до сетевых запросов. Нет "проверочного" обхода отключённого кода.

Первичные источники: [List Models](https://aistudio.google.com/api-reference/models/list-models), [Models: методы и нативные лимиты](https://aistudio.google.com/api-reference/models), [CountTokens](https://aistudio.google.com/api-reference/tokens/count-tokens), [изображения](https://aistudio.google.com/docs/image-understanding), [тариф](https://ai.google.dev/gemini-api/docs/pricing/), [квоты](https://aistudio.google.com/docs/rate-limits), [Billing/spend caps](https://aistudio.google.com/docs/billing#spend-caps), [условия](https://aistudio.google.com/docs/terms), [ключи](https://aistudio.google.com/docs/api-key).

## Работа после отдельного допуска

Доверенный оператор собирает локальный каталог с `manifest.json`: `version: 1`, стабильный `task_id`, новый `round_id`, точный `source_sha` цели, поле `brief` с текстом задачи (закреплено хешем manifest), массивы `context` и `images`. У каждого вложения есть `label`, относительный `path`, `sha256` байтов до нормализации, собственный Git `source_sha` (эталон может быть с другого commit); у изображения также `mime_type`. В первый ARP-круг включить реальные мобильный и настольный кадры цели, один-два лично принятых эталона и точно сформулированный вопрос дизайнеру. Не включать браузерную панель с аккаунтом, секреты, данные учеников, приватные черновики или посторонние пакеты. Изображения должны быть отдельно вручную просмотрены: проверка байтов и удаление метаданных **не** находят секреты или PII, которые видны в пикселях.

Доверенные настройки передают `NETOPS_GEMINI_DESIGNER_ENABLED=true`, `NETOPS_GEMINI_DESIGNER_VERIFIED_PROFILE_SHA256` и `NETOPS_GEMINI_DESIGNER_APPROVED_MANIFEST_SHA256`. Только после отдельного разрешения будущий запуск: `PYTHONPATH=.github python -m agent_runtime.designer --package <проверенный-каталог> --manifest-sha256 <утверждённый-хеш> --profile <утверждённый-профиль> --report <новый-файл-в-приватном-каталоге>`. На текущем коде команда с любыми настройками завершится `designer_transport_disabled`; нет новых workflow или покупок.

- PNG/JPEG проверяются по хешу/сигнатуре и реально декодируются. Передаются копии пикселей без исходных метаданных, нормализованные в PNG, с понятными метками. Текст и изображение становятся нативными `contents[].parts[].text` и `inlineData`. Провайдер видит снимки, а не их имена или имитацию контекста. В ledger попадают SHA, размеры, параметры бронирования и только числовое использование/код статуса; никаких изображений, запросов, ответа, stderr, заголовков, входного текста/путей или значения секрета. Перед резервом кандидаты в метаданные (включая идентификаторы задачи и итерации) проверяются на точные значения обоих переданных ключей и их Base64-представления; совпадение отклоняется без записи.
- До `countTokens` держим наихудшую подтверждённую цену этого вызова. Он считает тот же запрос (включая системный текст и картинки). До `generateContent` нужен отдельный успешно закреплённый CAS-резерв учитывающий native count с согласованным запасом, полную разрешённую длину ответа и reasoning. Проверка дня UTC и всей задачи работает для параллельных запусков и перехода через полночь. Известное согласованное usage оседает по верхним ставкам, неизвестное держит полный резерв; обнаруженное расхождение останавливает проект. Это локальный предохранитель, не обещание счета. Пропавший или неподходящий ответ не повторяется автоматически.
- Из провайдера принимается только завершённый текст в JSON: конкретное наблюдение для каждой метки, предложения с обоснованием и критериями, следующий творческий вопрос. Служебные размышления не сохраняются. Это **не** доказательство зрительного понимания: независимый человек сравнивает наблюдения с реальными кадрами. Валидированные предложения пишутся только в новый частный файл 0600 как недоверенный черновик; код никогда не исполняет рекомендации, не делает PR, не публикует отчёт или его вложения. Следующий круг получает новый `round_id`, подтверждённый оператором короткий отбор полезного контекста, обновлённые при необходимости снимки и отдельные резервы. Лимита «один творческий круг» нет; никаких автоматических повторов и обхода условий.

Офлайн-проверка: `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_gemini_designer*.py'`. Проверены только локальные входы и подставной транспорт/CAS. Аутентифицированный List Models, конкретный тариф проекта, данные настоящего провайдера и живой ARP-результат данным изменением не подтверждены.
