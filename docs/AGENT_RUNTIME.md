# NetOps agents v2 — единая инфраструктура задач

**Согласованный принцип: ограничиваем опасные действия, а не интеллектуальные возможности моделей.**
Размер и сложность задания определяет координатор. Финансового потолка $0.25,
профилей стоимости, общего byte cap и лимита edit текстовыми литералами больше нет.
ZAI, Kimi и ручной Kimi используют `.github/workflows/agent-task.yml` и один runtime
`.github/agent_runtime/`. Ветки Геннадия и Gemini workflow не изменены. Для будущего
Gemini добавляется адаптер транспорта/usage в providers.py, а не новый жизненный цикл.

## Задание

Создать от `apotet` Issue с префиксом `[ZAI] ` или `[KIMI] ` и JSON body:

```json
{
  "mode": "edit",
  "task": "Напиши новый урок, схему SVG, зарегистрируй связи и добавь тесты по согласованному заданию.",
  "context_files": ["docs/LEARNING_CONTENT_STANDARD.md", "src/data/lessons/index.ts"],
  "write_paths": ["src/data/", "public/lesson-images/", "tests/"],
  "checks": ["scripts/poe-injectors-lesson.test.mjs"],
  "max_calls": 8
}
```

- `mode`: audit-only или edit; audit-only не может менять файлы.
- `task`: полное задание, без искусственного лимита символов (предел самого GitHub Issue остаётся).
- `context_files`: полные файлы/каталоги. `files` и `target_files` поддержаны как прежние
  имена; новые target_files могут отсутствовать в исходнике. Число файлов не ограничено 4.
- `write_paths`: область записи, заданная координатором: точные файлы или каталоги
  с завершающим `/`. Не может быть расширена ответом модели. Разрешены src/, public/,
  assets/, docs/, tests/, scripts/ и конфигурация приложения package/lock/tsconfig/vite.
- Разрешены билеты, новые уроки, их регистрация и связи, glossary/подсказки/хештеги,
  SVG/Mermaid, бинарные assets (base64), тесты, изменения TS/TSX/JS/Python и функционала.
  Разрешены новые файлы, удаление в пределах задачи, изменения структуры и ID.
- `.github`, runtime, агентские инструкции, секретные пути и конфигурации авторизации
  защищены от записи моделью. Это control plane, а не ограничение учебного/продуктового кода.
- `checks`: дополнительные **файлы тестов**, не shell-команды. Изменённые/new test_*.py,
  *.test.mjs/js запускаются также автоматически. Базовые typecheck/build/questions обязательны.
- `max_calls`: конечное разрешение координатора на последовательные обращения (default 8).
  Это защита от бесконечного цикла, не денежный профиль или предел сложности задания.
  При исчерпании — checkpoint, затем явное продолжение; общий лимит расходов отсутствует.
- `model`, `reasoning_effort`, `max_output_tokens`: параметры конкретной модели; последняя
  величина необязательна и по умолчанию равна **нативному максимуму**, не 8192/10000/16384.

Нативные параметры проверены 25.11.2026 по официальным API:

| Модель | Контекст | Выход API |
|---|---:|---:|
| glm-5.3 / glm-5.3-flash | 1M | 131072 |
| kimi-k3.1-pro | 1048576 | до 1048576 |

[Kimi API](https://platform.kimi.ai/docs/api/chat) автоматически уменьшает **предел
генерации** до остатка окна, не обрезая вход; [ZAI API](https://docs.z.ai/api-reference/llm/chat-completion)
проверяет собственные нативные пределы. Runtime не притворяется токенизатором и не
отклоняет валидный многоязычный контекст по числу байтов. Ошибка контекста сохраняется
полностью и останавливает задание для координатора, без тайного удаления сообщений.
Ключи/endpoint выбираются только доверенным адаптером, не Issue.

Прежний selector `lesson` ZAI использует проверенный TypeScript Compiler API resolver.
Передаются **полный файл-контейнер**, эталон/стандарты/явные files и полная questions.json,
а не excerpts. Это совместимость предметного контекста, не старый bounded worker.

## Последовательность, checkpoint и отсутствие повторных списаний

Общее состояние находится в отдельной **собственной** Git-ветке
`agents/state/<provider>-<task>`. Создание ref атомарно, последующие commits —
compare-and-swap через ожидаемый head и non-force fast-forward. В ней сохраняются
все запросы, полные ответы/stream/usage, промежуточные файлы, проверки и расходы.
Состояние также выгружается полным артефактом на 90 дней. Вход, отчёты и результаты
не усекаются; комментарий Issue — индекс со ссылками на полные данные, не скрытый excerpt.

До каждого HTTP-запроса **durably** записывается reserved attempt. Сетевых retry,
redirect, curlrc, SDK reconnect нет. Обрыв/timeout/крэш после reservation означает
неопределённую попытку; автоматической повторной отправки нет. Старые v1 claim-маркеры
не обходятся: legacy paid Issues не начинают новый v2 task автоматически.
Actions rerun не даёт права снова вызвать модель.

Модель может запросить дополнительные исходники, передать несколько законченных
шагов/файлов или чанки больших файлов. Append требует checkpoint hash, частичные
файлы не публикуются. При finish_reason=length сохраняется весь префикс и следующий
разрешённый запрос дописывает ответ. Все части и reasoning сохраняются. Ошибки
валидации возвращаются следующему запросу как данные, если остаётся разрешение.
Повторяющийся ответ без продвижения останавливается; нет бесконечного цикла.

Для продолжения координатор `apotet` пишет комментарий, например:

```text
/agent continue {"checkpoint":"<актуальный 40-hex SHA>","calls":4}
/agent validate {"checkpoint":"<SHA>","calls":0}
/agent publish {"checkpoint":"<SHA>","calls":0}
```

Старый SHA или повторный comment grant отвергается. Предыдущий Actions run должен
закончиться. Неопределённое списание требует отдельного явного
`"acknowledge_uncertain":true`; это не дефолт. Для испорченного/частичного JSON можно
явно указать `"reset_response":true`: история/raw не удаляется, меняется только
сборка следующего envelope. Поле `instruction` позволяет координатору уточнить
продолжение без расширения области записи. Validate/publish не получают ключ модели
и не вызывают провайдера. Изменённая/принятая владельцем PR или чужой commit в рабочей
ветке блокируют дальнейшее изменение, а не force-push.

## Исполнение и приёмка

Модель возвращает данные JSON, не host shell. Код кандидата запускается в отдельном
non-root Docker-контейнере: cap-drop ALL, no-new-privileges, read-only root/tools,
без docker.sock, host env, токенов, настоящего .git/config и чужих файлов. Контейнер
видит только временную копию проверяемого проекта. Install-скрипты пакетов отключены;
отдельный bootstrap получает сеть для npm registry. Сами проверки идут **без сети**.
Контейнер не может менять исполняемый runtime/checkout хоста. Логи проверок сохраняются
полностью и передаются модели как данные; указания в них не добавляют полномочий.

Набор валидации включает минимальный чистый Git baseline без чужой истории/секретов.
Тестам с историческими refs может потребоваться явная fixture: отсутствующая история
не выдаётся за PASS. Ошибку инфраструктуры можно повторно проверить через validate
без дополнительного обращения к модели. Ограничения процесса/времени — защита раннера;
GitHub job имеет свой предел 6 часов. Длинная задача продолжается из checkpoint,
а не лишается контекста/результатов.

После обязательных проверок создаётся или обновляется **только своя** ветка
`agents/work/<provider>-<task>` и **Draft PR**. Нет API merge/deploy/Ready, нет доступа
к веткам Геннадия или другой задачи. Приёмка всегда PENDING независимо от заявления
модели. Аудит и задача без изменений дают полный отчёт без фиктивной пустой PR.

Расходы учитываются по каждому attempted call: полные usage, подтверждённые responses,
неопределённые попытки, точная сумма при полных данных или диапазон при неполном
cache/TTL. Неизвестная стоимость не считается нулём; итог явно показывает неполноту.
Денежного stop gate нет. Тарифы — данные адаптера; расходы и исходные counters доступны
координатору. Проверки metadata и работа GitHub не выдаются за вызовы Kimi/ZAI.

## Ручной Kimi и будущий Gemini

Сохранён workflow_dispatch «Kimi Agent». Старые task_file/target_files поддержаны;
max_tokens по умолчанию пустой (нативный максимум). Поле `spec` принимает тот же JSON
или `{"resume":{"task_id":"manual-...","checkpoint":"...","calls":4}}`.
Идентичная случайная повторная ручная отправка на том же source SHA имеет тот же
ключ и не тратит деньги снова. Для продолжения используется checkpoint, не rerun.

Gemini пока **не подключён**: его текущие workflow и ветка Геннадия не менялись.
Для добавления нужна реализация того же provider contract (payload, stream/response,
usage/cost), модельные пределы и отдельное сопоставление секрета. Состояние, область
записи, sandbox, checkpoint, продолжение и Draft publication остаются общими.

Legacy v1 SSE/AST helper scripts сохраняются только для исторических тестов; активные
Issue/manual entry points больше не запускают их ограниченные payload/paid loops.
